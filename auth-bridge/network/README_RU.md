# Единый аккаунт SinsWorld / Наруто / Solo Leveling

Один JAR SinsWorldAuth устанавливается на Bukkit/Spigot-совместимые Arclight-серверы с AuthMe 5.7.x. На существующем SinsWorld он работает в роли `primary`; на новых серверах — `satellite`. Это не отдельная копия пользователей: пароль, восстановление, сессии и выбор скина принадлежат центральному сервису. Лаунчер во всех темах использует тот же аккаунт. Наруто и Solo Leveling остаются «Скоро», пока их реальные адреса и сборки не настроены.

## Существующий SinsWorld — главный сервер

1. Остановите сервер и замените только `plugins/SinsWorldAuth-1.0.0.jar`. Сохраните существующие папки AuthMe и SinsWorldAuth, базу пользователей, TLS-ключи и настройки.
2. Оставьте `role: primary`. Аккаунты продолжают храниться в текущей базе AuthMe SQLite, перенос существующих пользователей не требуется.
3. В `network-servers` впишите реальные игровые адреса новых серверов, когда они появятся. Пустой адрес не активирует сервер.
4. После запуска плагин создаёт `plugins/SinsWorldAuth/private-network-keys.json`: отдельный секрет для каждого узла. Файл не публикуется и не входит в этот архив. Копируйте на каждый дополнительный сервер только его собственный ключ.
5. SkinsRestorer 15.x должен быть совместим с Java вашей сборки. Публичный API адаптера проверяется на 15.7.9 под Java 17. Новые версии плагина, требующие Java 25, на Java 17 ставить не нужно.

## Дополнительный сервер

1. Установите AuthMe 5.7.x, SkinsRestorer с совместимой Java-версией и тот же SinsWorldAuth JAR.
2. Используйте пример `naruto-config.yml` или `solo-config.yml`, впишите приватный `network-token` этого узла из центрального `private-network-keys.json`.
3. Скопируйте **публичный** сертификат главного сервера в `plugins/SinsWorldAuth/primary-certificate.pem`. Не копируйте приватный TLS-ключ. В комплекте сертификат соответствует HTTPS API текущего SinsWorld; если на хостинге сертификат изменился, используйте актуальный публичный файл.
4. В AuthMe дополнительного сервера выключите IP-сессии: `settings.sessions.enabled: false`. Не подключайте на этих узлах другие плагины автоматического входа. SinsWorldAuth откажется запускать satellite с включёнными IP-сессиями.
5. Перезапустите сервер. В режиме satellite второй публичный сервис регистрации не запускается. Вход разрешается только после центральной проверки одноразового билета, имени, offline UUID и адреса целевого сервера по HTTPS с проверкой сертификата.

AuthMe на satellite создаёт служебную запись с случайным непередаваемым паролем только после успешного центрального входа. Пользователь не регистрируется повторно. Команды AuthMe для игроков на satellite отключены: пароль и восстановление меняются через общий лаунчер. Служебные записи не являются копиями паролей главного сервера.

**Старые локальные аккаунты на дополнительных серверах не перезаписываются.** Если ник уже существует и не был создан этим плагином, вход отклоняется как конфликт миграции. Сначала сохраните резервную копию и отдельно согласуйте объединение старых данных; этот комплект сам ничего не удаляет и не захватывает существующие аккаунты. Для новых серверов используйте чистую базу AuthMe.

## Общий скин

Скин выбирается в разделе «Аккаунт» лаунчера: PNG 64×64/64×32 до 256 КБ, ник Minecraft или публичная HTTPS-ссылка. PNG/URL обрабатывает MineSkin через установленный SkinsRestorer; сервис может иметь очередь и ограничения. При необходимости настройте приватный серверный ключ MineSkin в SkinsRestorer. Ключ не передаётся лаунчеру.

Генерация выполняется в ограниченной фоновой очереди, смена — не чаще раза в минуту. Результат сохраняется в центральном SkinsRestorer. При следующем входе на satellite центральный сервис передаёт подписанное свойство скина; SkinsRestorer на этом сервере сохраняет и применяет его. Голова в лаунчере обновляется после сохранения, входа, выхода из игры и каждую минуту. Ошибка косметики не обходит и не отключает аутентификацию.

## Границы проверки

Комплект содержит исходники, тесты и готовый JAR. Автоматически проверяются авторизация владельца, одноразовость и привязка билета к серверу, TLS и публичные методы SkinsRestorer. Установка на реальные игровые серверы и вход настоящего игрока проверяются после размещения JAR и настройки узлов. Режим satellite пока не установлен на хостинг этим релизом.

Центральный HTTPS-сервис должен быть доступен при каждом новом входе; уже играющие пользователи не отключаются при его краткой недоступности. На клиентских сборках всех узлов нужен совместимый `sinsworld-auth-client` из комплекта. Переход из лаунчера на новые серверы активируется отдельно после задания реальных адресов, модпаков и версий Minecraft; текущие карточки Наруто и Solo Leveling пока остаются «Скоро».

Для воспроизводимых тестов Java используется официальный серверный JAR SkinsRestorer 15.7.9 (API bytecode Java 8, проверка выполняется на Java 17), а не Maven-библиотека этого релиза, собранная для Java 21. CI проверяет SHA-256 `ce1d84b6f4a978421f68fde3c95a99f06918897828eb425f5252822fd8b96419`. Для локальных тестов поместите этот JAR в `auth-bridge/server/build/compat/SkinsRestorer.jar`. Сам SkinsRestorer не включается в дистрибутив SinsWorldAuth.
