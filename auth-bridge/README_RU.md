# SinsWorld: AuthMe 5.7.0 + Arclight 1.20.1

Это отдельный тестовый комплект. Он подготовлен для предоставленного AuthMe 5.7.0-b2660, SQLite и Arclight / Forge 47.3.22. Существующие аккаунты остаются в AuthMe. На действующий сервер комплект автоматически не устанавливается. Вход на реальном сервере и его конкретная сборка Arclight ещё должны быть проверены после установки.

## Готовая настройка игроков

В лаунчер 1.2.2 уже встроены `https://104.204.218.124:8765` и публичный сертификат, предоставленный владельцем сервера. Игроку достаточно запустить `client/SinsWorldLauncher-AuthMePreview.exe` и войти либо зарегистрироваться. Запуск Configure-Auth.bat и ручное копирование сертификата не требуются. Старые пустые настройки API и старый сертификат автоматически заменяются встроенной привязкой; настройки памяти и игровая папка сохраняются. Адрес игры остаётся `sinsworld.minecraft.best`.

SHA-256 отпечаток доверенного сертификата: `BC:5E:9D:29:9E:65:AF:65:D5:55:59:06:CA:BB:2F:A8:3C:A3:D6:62:03:68:46:90:5A:A2:A7:66:D0:3A:6E:36`. Он действителен до 27 октября 2031 года, если сервер сохраняет ту же TLS-идентичность. При замене серверного ключа потребуется новая сборка с новым публичным сертификатом.

## Первичная установка сервера: HTTPS по IP без домена

Адрес авторизации: `https://104.204.218.124:8765`. Игровой адрес остаётся `sinsworld.minecraft.best`. Не удаляйте и не переназначайте игровой поддомен. Website connection в Bloom для этого варианта не нужна.

1. Сделайте резервную копию AuthMe и его базы. Остановите Arclight.
2. Загрузите содержимое `server/plugins` из ZIP в серверную папку `plugins`. Уже установленный AuthMe 5.7.0 сохраняется. Если есть старый SinsWorldAuth JAR, замените его новым, оставив ровно один JAR плагина.
3. В `plugins/SinsWorldAuth/config.yml` должны быть `tls-enabled: true`, `tls-ip: '104.204.218.124'`, `http-port: 8765`, `public-api-url: 'https://104.204.218.124:8765'`. Новый конфиг есть в комплекте; существующий плагин не перезаписывает автоматически старый конфиг. TCP-порт 8765 должен быть выделен в Bloom. Перезапустите сервер полностью.
4. Плагин создаст **на самом сервере** `private-tls.p12` (закрытый ключ, хранить только на сервере и в защищённой резервной копии) и `tls-certificate.pem` (публичный сертификат). Никаких закрытых ключей в GitHub/ZIP нет.
5. Через файловый менеджер Bloom откройте `plugins/SinsWorldAuth/tls-certificate.pem` и скопируйте весь текст с BEGIN/END CERTIFICATE. Не копируйте private-tls.p12 или private-auth-state.json.
6. В текущем комплекте публичный сертификат уже встроен в EXE. Закройте старый лаунчер и запустите новый EXE. Не удаляйте private-tls.p12 на сервере: новый ключ создаст другую TLS-идентичность.
7. Существующие аккаунты входят с паролем AuthMe. Регистрация без почты, новые пароли 12–30 символов. Сохраните выдаваемый код восстановления. После «Играть» мод передаёт одноразовый билет, AuthMe выполняет вход без `/login`.

Это локальный сертификат с явным доверием в лаунчере: обычный браузер покажет предупреждение о неизвестном издателе. Не отключайте проверку TLS. Доверие устанавливается через доступ владельца к панели Bloom, а не автоматическим скачиванием сертификата с непроверенного IP. Компьютеры получают публичный PEM внутри опубликованного EXE; пароли и закрытый ключ для этого не нужны. Сертификат привязан к точному адресу API; при изменении IP или замене ключа нужно повторить настройку. Срок сертификата — 5 лет, после этого потребуется замена. Публичный PEM можно распространять вместе с инструкцией; закрытый ключ — никогда.

Вариант с доменным HTTPS-прокси также сохранён: `tls-enabled: false`, действительный HTTPS-домен в public-api-url, в настройке лаунчера поле PEM пустое. Тогда используется обычное системное доверие к центрам сертификации.

Сборка и автоматические проверки не подтверждают установку на пользовательском сервере: живой вход нужно проверить после загрузки плагина и настройки сертификата.

## Совместимость и границы

- Используется существующая конфигурация AuthMe с offline UUID. Режим сервера не меняется автоматически; при online-mode=true эта версия моста отказывается запускаться. Премиальный/Yggdrasil вход — отдельный режим, он не заменяется неявно.
- Поддерживается предоставленный SQLite backend. База открывается только для чтения TOTP и отпечатка текущего хеша. Проверка и изменение паролей выполняются через API установленного AuthMe. При другой схеме/таблице или backend плагин останавливается с ошибкой конфигурации.
- Учётные записи с включённым AuthMe TOTP не получают автоматический вход: их второй фактор не обходится. Для них сохраняется обычный способ входа AuthMe.
- Не включайте IP-сессии и не снимайте принудительную авторизацию в AuthMe ради работы моста.
- На Arclight Trials 1.20.1 проверен исходный путь доставки custom payload в Bukkit messenger; скомпилированный мод использует сырой канал `sinsworld:auth`. Интеграционный запуск на пользовательском сервере ещё требуется.
- Лаунчер продолжает использовать основной список 44 модов. Дополнительно устанавливается ровно один мод входа, закреплённый встроенным хешем тестового EXE. Его установка идёт после общей проверки. При пустом auth_api_url дополнение не устанавливается.
- После выхода или вылета Minecraft лаунчер возвращает окно. Файл билета очищается клиентом перед отправкой и лаунчером при завершении процесса.

## Протокол и проверенные свойства

HTTPS API: POST `/v1/accounts/register`, `/v1/sessions/login`, `/v1/sessions/refresh`, `/v1/sessions/logout`, `/v1/account/recover`, `/v1/game/session`; GET `/health`.

Access token — 15 минут. Refresh token — 30 дней, с ротацией. Билет игры — 10 минут (чтобы дождаться первого запуска модпака), строго одноразовый, привязан к каноническому нику и offline UUID. Повторное предъявление отклоняется. При смене пароля либо включении TOTP старые доказательства больше не принимаются. Выход отзывает семейство текущей сессии; остальные устройства остаются действующими. После восстановления пароля отзываются все сессии аккаунта, а использованный код восстановления перестаёт действовать. Новая копия кода выдаётся при следующем успешном входе.

Сервер хранит только хеши refresh/recovery секретов в `plugins/SinsWorldAuth/private-auth-state.json`. Этот файл приватный; не добавляйте его в сборки клиента или репозиторий. Пароли, коды, билеты и токены в HTTP-журналы не записываются. В Minecraft передаются `accessToken=0` и путь к локальному файлу одноразового билета, без пароля/долгосрочного токена. Вход проверяет сервер, а не только лаунчер.

Клиент сверяет игровой адрес перед отправкой билета и не отправляет его чужому серверу или в одиночной игре. При ошибке моста AuthMe оставляет игрока неавторизованным. Это дополнение не включает шифрование игрового offline-mode TCP; транспорт HTTPS защищает обращения к API, а автоматическая авторизация не превращает offline-mode в Mojang online-mode.

Тесты Java покрывают неверный пароль, канонический UUID, истечение срока, одноразовость и конкурентный повтор билета, ротацию и сохранение refresh, выход с одного устройства, смену пароля, TOTP и восстановление. Python-тесты проверяют привязку игрового адреса/UUID, срок билета, старые пароли AuthMe и удаление локального файла. Это проверки компонентов, а не подтверждение установки на Bloom или успешного живого входа в Arclight.
