# SinsWorld: AuthMe 5.7.0 + Arclight 1.20.1

Это отдельный тестовый комплект. Он подготовлен для предоставленного AuthMe 5.7.0-b2660, SQLite и Arclight / Forge 47.3.22. Существующие аккаунты остаются в AuthMe. На действующий сервер комплект автоматически не устанавливается. Вход на реальном сервере и его конкретная сборка Arclight ещё должны быть проверены после установки.

## Что в комплекте

- `server/plugins/SinsWorldAuth-1.0.0.jar` — серверный Bukkit-плагин, класть в `plugins`, рядом с установленным AuthMe.
- `server/plugins/SinsWorldAuth/config.yml` — порт 8765 и игровой адрес `sinsworld.minecraft.best`.
- `client/SinsWorldLauncher-AuthMePreview.exe` — тестовый Windows-лаунчер 1.2.0 с входом через мост.
- `client/Configure-Auth.bat` — отдельное окно настройки HTTPS-адреса владельцем.
- `components/sinsworld-auth-client-1.0.0.jar` — Forge-мод передачи билета. При включённом AuthMe-режиме тестовый лаунчер устанавливает его сам с проверкой встроенного SHA-256. Вручную подкладывать его в обычный лаунчер не требуется: строгая проверка модов обычного лаунчера удалит мод, которого нет в его списке.

Исходные AuthMe.jar, authme.db, логи игроков и частные ключи в комплект не включены. Сохраняйте собственную папку `plugins/AuthMe` на сервере.

Тестовый EXE хранит настройки авторизации отдельно: `%APPDATA%/SinsWorldLauncherAuthPreview`. Настройки основного лаунчера не изменяются. Кеш игры используется существующий `%APPDATA%/SinsWorldLauncher/game`; второй Minecraft скачивать не требуется. Два лаунчера одновременно не запускаются. Тестовый EXE не переключается автоматически на основной канал обновлений: свежий тестовый комплект скачивается отдельно. Основной лаунчер по-прежнему сверяет свой обычный список модов и удаляет дополнительный клиентский мод, если запускается после теста.

## Установка на Bloom Host

1. Сделайте штатную резервную копию сервера через панель. Распакуйте папку `server/plugins` поверх папки `plugins` вашего сервера. Это добавляет новый SinsWorldAuth; данные AuthMe не заменяются.
2. В `Ports & Connections` выделен TCP-порт 8765 (`104.204.218.124:8765`). Если Bloom выделил иной порт, укажите его в `plugins/SinsWorldAuth/config.yml`, поле `http-port`.
3. На этом порту нажмите `Add Connection` → `A website`. Для HTTPS нужен отдельный свободный поддомен или собственный домен. На присланном скриншоте использован лимит 1/1: единственное имя `sinsworld.minecraft.best` занято Minecraft. Не переводите игровой поддомен в Website: он перестанет быть игровым. Уточните у Bloom возможность дополнительного поддомена либо добавьте собственный домен по инструкции панели.
4. После создания подключения Bloom самостоятельно выдаёт HTTPS-сертификат. Запишите **фактически созданный** URL. В конфигурации плагина задайте `public-api-url: 'https://ФАКТИЧЕСКИЙ-ДОМЕН'` без путей `/health` и `/v1`. Значение по умолчанию пустое, поэтому операции аккаунтов выключены до явной настройки владельцем.
5. Перезапустите Arclight: новые порты Bloom также применяются после перезапуска. В консоли должны успешно включиться AuthMe и SinsWorldAuth.
6. Откройте `https://ФАКТИЧЕСКИЙ-ДОМЕН/health`. Ожидается `service: SinsWorldAuth`, `protocol: 1`, `configured: true`. До задания public-api-url health может отвечать `configured: false` — это означает, что плагин запущен, а вход ещё выключен.
7. Полностью закройте лаунчер. В папке `client` запустите `Configure-Auth.bat`, введите фактический HTTPS URL и сохраните. Окно проверяет сертификат, отсутствие редиректов, `/health` и готовность моста. Затем запустите `SinsWorldLauncher-AuthMePreview.exe`.
8. Войдите старым ником и паролем AuthMe либо зарегистрируйтесь без почты. При первом входе через мост сохраняйте выданный одноразовый код восстановления. Для новых паролей по умолчанию требуется 12–30 символов; старые пароли AuthMe длиной от 5 символов подходят для входа.
9. Нажмите «Играть»: сначала проверяются Minecraft, Java и разрешённые моды, затем устанавливается проверенный мод входа и выдаётся свежий билет. Лаунчер соединяется с `sinsworld.minecraft.best`. При успешной проверке билета AuthMe авторизует игрока без команды `/login`.

Официальная инструкция Bloom: https://docs.bloom.host/ports-and-connections — раздел Websites. Адрес `104.204.218.124:8765` является внутренним HTTP-входом размещённого приложения за HTTPS-прокси; в лаунчер вводится HTTPS-домен, а не этот IP с портом. Плагин не является веб-сайтом панели и не использует учётную запись Bloom.

## Совместимость и границы

- Используется существующая конфигурация AuthMe с offline UUID. Режим сервера не меняется автоматически; при online-mode=true эта версия моста отказывается запускаться. Премиальный/Yggdrasil вход — отдельный режим, он не заменяется неявно.
- Поддерживается предоставленный SQLite backend. База открывается только для чтения TOTP и отпечатка текущего хеша. Проверка и изменение паролей выполняются через API установленного AuthMe. При другой схеме/таблице или backend плагин останавливается с ошибкой конфигурации.
- Учётные записи с включённым AuthMe TOTP не получают автоматический вход: их второй фактор не обходится. Для них сохраняется обычный способ входа AuthMe.
- Не включайте IP-сессии и не снимайте принудительную авторизацию в AuthMe ради работы моста.
- На Arclight Trials 1.20.1 проверен исходный путь доставки custom payload в Bukkit messenger; скомпилированный мод использует сырой канал `sinsworld:auth`. Интеграционный запуск на пользовательском сервере ещё требуется.
- Лаунчер продолжает использовать основной список 44 модов. Дополнительно устанавливается ровно один мод входа, закреплённый встроенным хешем тестового EXE. Его установка идёт после общей проверки. При пустом auth_api_url дополнение не устанавливается.
- После выхода или вылета Minecraft лаунчер возвращает окно. Файл билета очищается клиентом перед отправкой и лаунчером при завершении процесса.

## Протокол и проверенные свойства

HTTPS API: POST `/v1/accounts/register`, `/v1/sessions/login`, `/v1/sessions/refresh`, `/v1/sessions/logout`, `/v1/account/recover`, `/v1/game/session`; GET `/health`.

Access token — 15 минут. Refresh token — 30 дней, с ротацией. Билет игры — 90 секунд, строго одноразовый, привязан к каноническому нику и offline UUID. Повторное предъявление отклоняется. При смене пароля либо включении TOTP старые доказательства больше не принимаются. Выход отзывает семейство текущей сессии; остальные устройства остаются действующими. После восстановления пароля отзываются все сессии аккаунта, а использованный код восстановления перестаёт действовать. Новая копия кода выдаётся при следующем успешном входе.

Сервер хранит только хеши refresh/recovery секретов в `plugins/SinsWorldAuth/private-auth-state.json`. Этот файл приватный; не добавляйте его в сборки клиента или репозиторий. Пароли, коды, билеты и токены в HTTP-журналы не записываются. В Minecraft передаются `accessToken=0` и путь к локальному файлу одноразового билета, без пароля/долгосрочного токена. Вход проверяет сервер, а не только лаунчер.

Клиент сверяет игровой адрес перед отправкой билета и не отправляет его чужому серверу или в одиночной игре. При ошибке моста AuthMe оставляет игрока неавторизованным. Это дополнение не включает шифрование игрового offline-mode TCP; транспорт HTTPS защищает обращения к API, а автоматическая авторизация не превращает offline-mode в Mojang online-mode.

Тесты Java покрывают неверный пароль, канонический UUID, истечение срока, одноразовость и конкурентный повтор билета, ротацию и сохранение refresh, выход с одного устройства, смену пароля, TOTP и восстановление. Python-тесты проверяют привязку игрового адреса/UUID, срок билета, старые пароли AuthMe и удаление локального файла. Это проверки компонентов, а не подтверждение установки на Bloom или успешного живого входа в Arclight.
