# Обновления SinsWorld через GitHub Releases

Каналы настроены на публичный репозиторий `Zairez1/SinsWorldLauncher`. Клиентский EXE не содержит токенов GitHub.

## 1. Структура

Можно использовать один репозиторий для двух каналов или два разных:

| Настройка | Значение |
| --- | --- |
| launcher_repository | `ваш-логин/ваш-репозиторий` |
| launcher_release | `launcher-current` |
| mods_repository | `ваш-логин/ваш-репозиторий` |
| mods_release | `mods-current` |

Вводится именно `owner/repository`, без `https://github.com/`. Релизы должны быть опубликованы, не Draft. Исходники и ZIP репозитория автоматически модами не становятся: нужны приложенные к Release assets.

Разные теги выбраны намеренно: публикация нового мода не должна случайно стать «последним релизом лаунчера».

## 2. Лаунчер

1. Увеличьте `VERSION` в `version.py`, например до `1.0.1`.
2. Соберите EXE через `build_windows.bat` на Windows 10/11 с Python 3.11 и Edge WebView2 Runtime.
3. В `dist/` появятся `SinsWorldLauncher.exe` и `launcher-manifest.json` с реальными размером и SHA-256.
4. Создайте/откройте GitHub Release с тегом `launcher-current`.
5. Загрузите EXE, затем манифест. Не загружайте манифест раньше EXE. При публикации в промежуточном состоянии проверка суммы может временно не пройти — установка при этом не состоится.
6. В новой поставке заполните `launcher_repository` в корневом `config.json` до сборки. В уже установленной — через настройки.

При запуске проверяется только этот релиз. Если версия новее, EXE скачивается в отдельную временную папку, сверяется размер и SHA-256, затем PowerShell-помощник ждёт закрытия старого процесса и заменяет EXE. Предыдущий EXE сохраняется рядом как `.previous`. При ошибке перемещения он возвращается. Настройки и игра находятся в `%APPDATA%/SinsWorldLauncher` и не заменяются.

Автозамена EXE выполняется только в собранном Windows-приложении. Запуск из Python показывает наличие новой версии, но не подменяет Python-интерпретатор и исходники. Для папки установки должны быть права записи. Права администратора автоматически не запрашиваются.

Сетевая проверка и скачивание идут с таймаутами. Публичный GitHub API имеет лимит частоты; при ограничении отображается ошибка, а не ложный результат «обновлений нет». Доступна повторная попытка или переход к настройкам.

### GitHub Actions

В пакете есть `.github/workflows/windows.yml`. Поместите содержимое папки проекта в корень своего репозитория.

- Push изменений приложения в main или ручной запуск Actions → Build SinsWorld for Windows собирает EXE и публикует его в `launcher-current`.
- CI автоматически задаёт версию вида `1.1.<номер запуска>` и вшивает адрес текущего репозитория. Для новой версии достаточно опубликовать изменение исходников в main. Изменения только документации не запускают сборку.
- Workflow использует временный `github.token` в CI. Личные PAT не вшиваются в лаунчер.

Windows workflow успешно выполнен на GitHub; первая версия EXE — 1.1.1.

## 3. Моды

Для повторной публикации набора откройте Actions → Publish SinsWorld mods → Run workflow. Workflow умеет импортировать первоначальную публичную папку Яндекс Диска. Источник можно изменить в поле source_url. Если в репозитории есть файлы mods/*.jar, используются они. После первоначального переноса игроки обращаются только к GitHub Releases.


Подготовьте папку `mods` с JAR-файлами вашей сборки и выполните:

```powershell
python tools/make_release.py mods --folder mods --output mods-manifest.json
```

Создайте Release с тегом `mods-current`. Приложите к нему каждый JAR отдельным asset и `mods-manifest.json`. Имена JAR должны совпадать с манифестом, включая регистр. Обновляя сборку, сначала загрузите новые JAR, затем новый манифест. После этого старые assets можно удалить из Release, если они больше не упоминаются.

Minecraft и Forge по умолчанию остаются прежними: `1.20.1` и `1.20.1-47.3.22`. Если меняете версии, согласованно меняйте корневой `config.json` и аргументы генератора манифеста. Несовместимый манифест отклоняется.

Перед игрой или по кнопке «Проверить моды» лаунчер:

1. Получает список и суммы из `mods-manifest.json`.
2. Пропускает уже актуальные файлы по размеру и SHA-256.
3. Сначала скачивает и проверяет все изменившиеся файлы во временную папку.
4. Заменяет проверенные файлы, сохраняя резервные копии до успешного завершения операции.
5. Удаляет только исчезнувшие из манифеста моды, которыми он управлял ранее, и только если они не изменены пользователем.

Неуправляемые JAR, локально изменённые старые моды, сохранения, скриншоты и настройки не удаляются. При переходе со старого Яндекс Диска вручную проверьте папку `mods` на дубликаты версий: новый updater не может достоверно определить владельца ранее установленных файлов.

Если Minecraft запущен из этого экземпляра лаунчера, обновление модов заблокировано. Не запускайте несколько экземпляров лаунчера для одной папки игры.

## 4. Доверие к публикациям

SHA-256 и HTTPS защищают от повреждённого скачивания и подмены сторонним сетевым узлом. Манифест и EXE находятся в одном доверенном GitHub-репозитории; независимой криптографической подписи издателя в этом проекте пока нет. Защитите аккаунт владельца репозитория. Произвольные внешние URL в манифестах не принимаются.
