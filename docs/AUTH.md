# Аккаунты и вход на сервер

В исходном лаунчере была только локальная запись ника с offline UUID. Она не является регистрацией и не отменяет AuthMe. В присланном архиве нет API аккаунтов, серверного плагина или базы пользователей.

В новой версии есть формы входа, регистрации и восстановления без почты, а также адаптер HTTPS API. Если `auth_api_url` пустой, регистрация не имитируется: интерфейс объясняет, что сервис не подключён. Можно сохранить локальный ник как в прежней версии; это явно подписано как локальный режим. Он не подтверждает личность игрока перед сервером.

## Контракт собственного сервиса

`auth_api_url` — корень HTTPS-сервиса. Запросы JSON, редиректы с учётными данными запрещены. Пароли не сохраняются в конфигурацию. Возврат API не должен содержать лишних секретов.

| POST-маршрут | Вход |
| --- | --- |
| `/v1/accounts/register` | `nickname`, `password` |
| `/v1/sessions/login` | `nickname`, `password` |
| `/v1/sessions/refresh` | `refresh_token` |
| `/v1/sessions/logout` | Bearer access token |
| `/v1/account/recover` | `nickname`, `recovery_code`, `password` |
| `/v1/game/session` | Bearer access token |

Вход, регистрация и обновление сессии возвращают:

```json
{
  "account": {"id": "постоянный UUID", "name": "Player"},
  "access_token": "короткоживущий токен",
  "refresh_token": "отзывной токен",
  "recovery_code": "только при регистрации/перевыпуске"
}
```

Refresh token сохраняется через системное защищённое хранилище `keyring`, если выбрано «Запомнить меня». При недоступности хранилища показывается предупреждение; пароль или токен не записывается в открытый JSON. Восстановление должно быть реализовано и проверяться сервером, включая одноразовость кода.

Для игры `/v1/game/session` возвращает `name`, `uuid`, `access_token`. Они должны соответствовать аккаунту. Собственная игровая сессия требует совместимой Yggdrasil-службы и проверки личности на игровом сервере/прокси. Одного входа в лаунчере недостаточно.

Для такого режима положите проверенный `authlib-injector.jar` в корень проекта до сборки и задайте в config:

- `yggdrasil_url`: HTTPS-адрес своей службы игровых сессий;
- `authlib_injector_sha256`: точный SHA-256 JAR.

EXE-сборка включит этот JAR, если он существует. При отсутствии JAR или неверном хеше игра с собственной сессией не запускается. В сам пакет authlib-injector не добавлен и готовый сервис авторизации не предоставлен.

Настройте проверку своей службы на сервере и выполните тест подмены ника. Лишь после этого можно обещать автоматический вход без `/login`. Не включайте доверие к произвольному нику, IP или локальному профилю вместо проверки сессии.

Документация: https://yushijinhun.github.io/authlib-injector/en/launcher-technical-specification.html
